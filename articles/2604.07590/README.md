# DCD: Доменно-ориентированный дизайн для контролируемой генерации с дополнением (RAG)

## Tags
- Retrieval Augmented Generation
- Knowledge Hierarchy
- Domain Oriented Design
- Multi Stage Routing
- Information Retrieval
- LLM Guardrails
- Semantic Search

## TL;DR
Авторы представляют DCD (Domain–Collection–Document) — архитектурный подход к RAG, который структурирует знания иерархически и использует многоэтапную маршрутизацию запросов. Это повышает точность поиска и надежность генерации без необходимости дообучения языковой модели.

## Краткое описание
Стандартные RAG-системы часто демонстрируют снижение качества при работе с гетерогенными данными и сложными многошаговыми запросами из-за плоской структуры знаний и отсутствия явных рабочих процессов. Авторы предлагают DCD — доменно-ориентированный дизайн, который вводит явную иерархию знаний (Домен — Коллекция — Документ) и контролируемый пайплайн обработки запросов.

Система использует LLM для маршрутизации запроса по иерархии, что позволяет ограничить область поиска релевантными подмножествами данных. Архитектура дополняется «умным» чанкингом с перекрытием, гибридным поиском и встроенными механизмами валидации (guardrails) для предотвращения галлюцинаций. Эксперименты на синтетическом наборе данных показывают, что DCD значительно превосходит стандартный (Naive) RAG по показателям полноты контекста и фактической точности, обеспечивая при этом предсказуемость работы системы в прикладных сценариях.

## Основные идеи
- Иерархическая декомпозиция знаний на уровни Домен, Коллекция и Документ.
- Многоэтапная маршрутизация запросов с использованием структурированных выходов LLM.
- Ограничение области поиска семантически однородными регионами для снижения помех.
- Использование «умного» чанкинга с перекрытием для сохранения контекстной целостности.
- Внедрение механизмов guardrails для ранней валидации ответов и предотвращения галлюцинаций.

## Какую проблему решает статья
- Деградация качества RAG при работе с большими гетерогенными корпусами документов.
- Неэффективность поиска при многошаговых запросах, требующих обращения к разным контекстным областям.
- Чувствительность систем к параметрам сегментации текста.
- Отсутствие контроля над процессом генерации и валидации ответов в стандартных линейных пайплайнах.

## Метод
Архитектура DCD переводит RAG из линейного процесса в иерархический:
- **Маршрутизация:** DCD Router последовательно выбирает наиболее релевантный домен, коллекцию и документ, используя структурированные JSON-ответы от LLM.
- **Сегментация:** Применяется sliding-window чанкинг (перекрытие 5–10%) с обогащением метаданными, описывающими позицию фрагмента в иерархии.
- **Валидация:** Система включает двухкомпонентные guardrails: фильтрацию запросов по словарям и проверку сгенерированного ответа на соответствие контексту и отсутствие галлюцинаций.
- **Fallback:** На каждом уровне иерархии определены элементы по умолчанию для обеспечения отказоустойчивости.

## Главные результаты
- **Context Recall:** DCD достигает 0.95 против 0.59 у Naive RAG.
- **Factual Accuracy:** 0.89 против 0.40 у базового подхода.
- **Retrieval Coverage Score:** 1.76 против 1.28.
- **Answer Relevance:** Результаты сопоставимы (0.86 у DCD против 0.87 у Naive), что подтверждает сохранение качества генерации при значительном улучшении точности поиска.

## Важные концепции
- **Семантическая однородность:** Предположение, что поиск работает лучше, если документы в рамках одной области конкурируют только с семантически близкими источниками.
- **Структурированная маршрутизация:** Использование LLM как классификатора для навигации по дереву знаний, что делает процесс прозрачным и воспроизводимым.
- **Guardrails:** Параллельная проверка первых токенов ответа для блокировки нежелательного контента без увеличения задержки (latency).

## Ограничения
- **Сложность настройки:** Требует предварительной иерархической организации данных, что усложняется при росте объема и гетерогенности базы.
- **Зависимость от структуры:** Эффективность снижается на полностью неструктурированных данных, где метод может деградировать до уровня продвинутых стандартных RAG.
- **Вычислительные затраты:** Многоэтапная маршрутизация требует дополнительных вызовов LLM.

## Практическое применение
- Корпоративные системы анализа документации.
- Техническая поддержка и клиентские сервисы с узкоспециализированными базами знаний.
- Системы, требующие высокой фактической точности и возможности аудита процесса поиска.

## Итоговые выводы
- DCD значительно повышает точность поиска в сложных RAG-системах.
- Иерархическая структура минимизирует попадание нерелевантного контекста в генерацию.
- Метод обеспечивает высокую фактическую точность и снижение галлюцинаций.
- Основной ценой является необходимость предварительной структуризации знаний.
- Подход идеально подходит для задач, где важна предсказуемость и контроль над источниками информации.
