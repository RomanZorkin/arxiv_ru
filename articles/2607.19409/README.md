# FORCE-Bench: Бенчмарк и набор инструментов для оценки агентных систем в корпоративных финансах

## Tags
- Agentic AI
- Enterprise Finance
- Benchmarking
- LLM Evaluation
- ERP Systems
- Tool Use
- Operational Finance

## TL;DR
FORCE-Bench — это специализированный бенчмарк для оценки ИИ-агентов в операционных финансах. Он использует 251 экспертный запрос и рубрику из восьми метрик для проверки точности, обоснованности и качества работы агентов в условиях реальных ограничений по времени и доступу к данным.

## Краткое описание
Статья представляет FORCE-Bench (Financial Obligations, Research, and Composition Evaluation) — первый бенчмарк, ориентированный на рабочие процессы в операционных финансах. В отличие от общих LLM-тестов, FORCE-Bench оценивает агентов в трех критических сценариях: исследование финансовых обязательств (ERP-системы), анализ эффективности компаний (публичные данные) и генерация бизнес-отчетов.

Авторы решают проблему нехватки инструментов для оценки надежности ИИ-агентов в корпоративной среде, где важны не только общие способности модели, но и соблюдение доменных правил, точность цитирования и работа в условиях жестких ограничений по задержке (latency). Результаты показывают, что специализированные агенты (например, Finance Agent для Microsoft 365 Copilot) значительно превосходят универсальные модели, особенно в задачах, требующих точного извлечения данных из ERP-систем.

## Основные идеи
- Внедрение восьми профессиональных метрик качества (точность, цитирование, глубина, обоснованность и др.).
- Оценка агентов в условиях реальных ограничений по времени (latency-bounded).
- Использование синтетической среды Dynamics 365 Finance для воспроизводимых ERP-запросов.
- Применение LLM-судьи с рубриками для детального анализа причин ошибок.
- Сравнение специализированных агентов с универсальными API.

## Какую проблему решает статья
Существующие бенчмарки (MMLU, AgentBench, ToolBench) ориентированы на общие способности или розничные сценарии. Они не учитывают специфику корпоративных финансов: необходимость работы с внутренними ERP-системами, строгие требования к цитированию источников, соблюдение политики компании и работу в условиях жестких временных рамок, характерных для реальных бизнес-процессов.

## Метод
- **Датасет:** 251 экспертно-аннотированный запрос, разделенный на три типа: обязательства (ERP), эффективность компаний (публичные данные) и бизнес-отчеты.
- **Оценка:** Рубрика из 8 измерений, где каждое измерение состоит из проверяемых утверждений. Оценка проводится LLM-судьей (GPT-5.2) по шкале 0.0–1.0.
- **Harness:** Инструментарий для тестирования агентов, поддерживающий работу с ERP-системами через MCP-серверы и веб-поиск.
- **Статистика:** Использование линейных смешанных моделей (LMM) для корректного сравнения производительности агентов с учетом сложности отдельных вопросов.

## Главные результаты
- **Finance Agent** демонстрирует превосходство по всем 8 метрикам, особенно в точности (0.77 против 0.40–0.67 у конкурентов).
- **Влияние задержки:** Ограничение в 60 секунд существенно снижает качество ответов, так как агенты не успевают выполнить многошаговые цепочки вызовов инструментов.
- **Компромисс:** Увеличение "усилий на рассуждение" (reasoning effort) улучшает качество, но при жестких лимитах времени приводит к таймаутам и падению точности.

## Важные концепции
- **Рубрикатор:** Переход от бинарной оценки (успех/провал) к многомерному анализу, позволяющему понять, почему агент ошибся (например, проблема в цитировании или в глубине анализа).
- **ERP-grounding:** Способность агента корректно взаимодействовать с внутренними системами учета, что является критическим навыком для корпоративного ИИ.
- **Latency-bounded evaluation:** Оценка производительности в условиях реальных бизнес-ожиданий по времени отклика.

## Ограничения
- **Размер датасета:** 251 запрос ограничивает статистическую мощность для глубокого сегментированного анализа.
- **Co-development:** Finance Agent разрабатывался параллельно с бенчмарком, что могло дать ему преимущество.
- **LLM-судья:** Возможная предвзятость судьи (self-preference bias) при оценке ответов разных моделей.
- **Инфраструктура:** Для воспроизведения ERP-тестов требуется лицензия и доступ к Dynamics 365.

## Практическое применение
- **Enterprise Automation:** Разработка и аудит ИИ-агентов для финансового департамента.
- **Benchmarking:** Использование методологии для оценки надежности агентов в других высокорегулируемых отраслях.
- **System Design:** Оптимизация конфигураций агентов (reasoning effort vs. latency) для production-систем.

## Итоговые выводы
- Специализированные агенты значительно надежнее универсальных в финансовых задачах.
- Точность извлечения данных из ERP — ключевой дифференциатор качества.
- Ограничения по времени (latency) являются критическим гиперпараметром для агентных систем.
- Многомерная рубрика — лучший способ диагностики ошибок ИИ в бизнесе.
- FORCE-Bench предоставляет открытую базу для воспроизводимых исследований в области корпоративного ИИ.
